# i18n messages (Paraglide)

i18n is **Paraglide JS** (inlang): messages are compiled to tree-shakeable functions at build time — there is no runtime dictionary lookup. When unsure about message format, params, or pluralization, consult https://inlang.com/m/gerre34r/library-inlang-paraglideJs before assuming; Paraglide's format is not i18next's.

## Adding copy

1. Add the key to **every** locale file in `messages/` (`nl-NL.json` is the base locale — check `project.inlang/settings.json`). A key missing from one locale is a bug.
2. Follow the key conventions in `CLAUDE.md`: `{feature}_{concept}` (`login_submit`, not `field_submit`); `common_` only for structural UI strings; blank lines between logical groups; identical strings in different features still get separate keys.
3. Use it:

```tsx
import * as m from "lib/paraglide/messages";
// ...
<Button>{m.login_submit()}</Button>
```

Messages are **functions** — call them. Parameters pass as an object: `m.greeting({ name })`.

`src/lib/paraglide/` is generated by the Vite plugin; never edit it. New keys appear after the plugin recompiles (dev server picks up message-file changes; restart if it doesn't).

## Never hardcode copy

No user-facing string literals in components — including error fallbacks, `aria-label`s, and page titles. If you spot an existing hardcoded string while editing a file, extract it to a message.

## Locale mechanics (already wired — know, don't rebuild)

- **Strategy order** (`vite.config.ts`): `url` → `localStorage` → `baseLocale`. URLs are localized per `router-i18n.ts` (see the `adding-a-route` skill); the root route handles locale redirects and canonical links.
- **Switching**: `setLocale(locale)` from `lib/paraglide/runtime` — see the language `Select` in `app-header.tsx`. Reading: `getLocale()`, or the `useLocale()` hook (`src/lib/i18n.ts`) when you need an `Intl.Locale`.
- **Zod messages**: `loadZodLocale` (`src/lib/i18n.ts`) configures zod's locale so generated-schema validation errors are translated. It is called on locale change in `main.tsx`. When adding a locale, check zod ships it (`zod/locales`) and extend the `zodLocales` map.
- **`<html lang>`** is synced in `main.tsx`.

## Adding a locale

1. Add to `locales` in `project.inlang/settings.json`.
2. Create `messages/<locale>.json` with all keys.
3. Add per-route pathnames for it in `router-i18n.ts` (the types will demand it).
4. Extend `zodLocales` in `src/lib/i18n.ts`.
